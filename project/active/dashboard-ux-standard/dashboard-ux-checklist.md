# 대시보드 UX 표준 체크리스트 (v0.1 draft)

새 대시보드를 만들거나 기존 대시보드를 점검할 때 이 체크리스트를 기준으로 확인한다.
디자인(컬러·폰트·톤)은 자유지만, 아래 항목은 **고객 UX를 위해 강제**한다.

---

## A. 신뢰 / 투명성

고객이 숫자를 보고 "이거 믿어도 되나?"라는 의문이 들지 않게 한다.

- [ ] **원본 데이터 기간 표기** — 좌측 하단(또는 푸터)에 "데이터 기준: 2026-08-01 ~ 2026-09-22" 형태로 항상 노출
- [ ] **지표 정의 툴팁** — ROAS, CPA 등 계산식이 있는 지표는 hover 시 "매출/광고비, VAT 제외" 같은 정의 노출. 지표 정의는 경우의 수가 다양해서 오해를 줄이기 위해 추가
- [ ] **비교 기준 라벨링** — 전일/전주/전월 대비 화살표(▲▼)에는 항상 "vs 지난 7일" 등 비교 기준을 함께 표기. 숫자만 있으면 오해 발생

## B. 탐색 / 필터링

- [ ] **필터 섹션 상단 고정(sticky)** — 스크롤과 무관하게 최상단 필터 바는 고정
- [ ] **기간 프리셋 버튼** — 오늘 / 7일 / 30일 / 이번달 / 지난달 최소 제공
- [ ] **적용 필터 칩(chip) 노출** — 현재 선택된 필터를 상단에 칩 형태로 보여주고 개별 X로 해제 가능하게
- [ ] **필터 상태 → URL 쿼리 반영** — 필터를 바꾸면 URL이 갱신되어, 링크 복사 시 "보고 있던 화면 그대로" 전달 가능 (C-1과 연동 필수)
- [ ] **Back-to-top 버튼** — 아래로 스크롤 시 우하단(또는 좌하단) 고정 버튼으로 최상단 복귀

## C. 커뮤니케이션 / 공유

- [ ] **[링크 복사] 버튼** — 우측 상단 고정 위치. 클릭 시 현재 필터 상태가 반영된 URL을 클립보드에 복사
- [ ] **인쇄/캡처 대응 뷰** — 보고서에 바로 붙여넣을 수 있도록 "내보내기(PNG/인쇄용 뷰)" 옵션 고려. 최소한 캡처했을 때 sticky 요소가 화면을 가리지 않는지 확인

## D. 레이아웃 / 성능 / 접근성

- [ ] **오픈 속도 우선** — 첫 화면은 당월 데이터만 우선 로드, 나머지 기간은 지연 로딩 + 가드. 재시도보다 요청 수 자체를 줄이는 방향
- [ ] **로딩 스켈레톤** — 데이터 fetch 중 빈 화면 대신 스켈레톤 UI로 레이아웃 흔들림 방지
- [ ] **반응형 레이아웃 표준** — 그리드는 `minmax(0,1fr)`, 패널은 `min-width:0`, 표는 개별 스크롤, 페이지 자체는 가로 스크롤 0
- [ ] **스크롤바 hover 전 숨김** — 전역 CSS로 일괄 처리, 패널별 개별 지정 금지
- [ ] **모바일 대응** — 표는 가로 스크롤, 차트는 세로 스택
- [ ] **섹션 타이틀/소제목 텍스트 스타일 일관성** — 폰트 크기/굵기/색상을 전체 대시보드에서 통일. 특정 영역만 소제목이 커지거나 스타일이 튀지 않게
- [ ] **파이차트는 legend:false + HTML legend 분리, canvas 고정 크기(responsive:false)** — Chart.js 내장 legend 사용 시 원 크기가 달라지는 문제 방지
- [ ] **점검은 프록시 URL + refresh=1로** — 통합시트 직접 gviz 호출 401은 정상(의도된 차단), 데이터 유무 판단은 반드시 캐시 우회 확인

---

## 사용 방법

새 대시보드를 만들 때 클로드코드 프롬프트에 이 문서 링크를 참고자료로 넣고 "이 체크리스트 반영해서 작업해줘"라고 요청하면 된다. 전부 강제는 아니며, 광고주 요구사항과 상충하면 팀 채널에서 논의 후 예외 처리한다. 새로운 규칙이 실전에서 나오면 이 문서에 추가한다.
